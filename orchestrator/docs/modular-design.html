Orchestrator modules: the non-gray side of the architecture

Peter owns the three specialists in the gray box: Lender Match, Risk and Policy. This page covers everything else in the architecture diagram: the Orchestrator, Intake, Explainer, Critic, the borrower and counselor loop, and the Stop step. Each box becomes its own Python package with one job, a small public interface, and a rule-based fallback so the whole loop runs and tests without an API key.

Packages

Everything lives under orchestrator/navigator/. A package's node.py is the only thing graph.py imports from it; the other files are plain functions that tests call directly.

Orchestrator

core/

Decides what runs, keeps the case file, and wraps Peter's agents so they can't crash a session.

  • case.pyload, save and query the case file
  • routing.py"rerun only what changed" table, editable-field allow-list
  • specialists.pytimeout and error guard around each gray agent
  • stopping.pymax rounds, "nothing material changed", end reasons
  • escalation.pywhen a counselor must look before the borrower does
  • CaseFile.log()append-only audit log ("how did we get here"), kept on the case file itself
Shared service

llm/

The one place that calls Claude. Every agent uses it the same way.

  • client.pystructured output into a Pydantic model, refusal handling, LLMUnavailable when off or failing

Off by default in tests (NAVIGATOR_LLM=off), so agents fall back to their rule-based versions.

intake/

Builds a complete, consistent profile and turns free-text what-ifs into field changes.

  • checks.pyconsistency checks beyond field types (DTI over 50%, townhouse type)
  • questions.pyturns problems into at most 3 plain questions
  • extractor.pyLLM: borrower's words to a profile draft or a what-if

Agent

explainer/

Writes the report. Colors and numbers come from code; the LLM only writes the words around them.

  • signals.pythe two traffic lights, computed by rule
  • facts.pyevery number the report may state, with its source
  • template.pydeterministic report (fallback and evaluation baseline)
  • writer.pyLLM report from the facts, answering Critic fixes
  • node.pypicks writer or template
Agent

critic/

Checks every draft before a person sees it.

  • rules.pydecision language, steering, disclaimer, numbers match facts, citations real, signals match, protected traits
  • reviewer.pyLLM second opinion (smaller model, different prompt)

The contract with Peter's agents

A specialist is any function fn(state) -> {"<name>": result_dict} that reads the current scenario and returns a LenderMatchResult, RiskResult or PolicyResult from mrn_shared. That is already how his three agents work, so nothing changes for him.

core/specialists.guarded() wraps each one. If it raises or runs past its timeout, the wrapper returns a result with source="unavailable", the report says not assessed, and an event is logged. The report always goes out, and no stand-in numbers are made up.

One round, step by step

  1. Intake merges the borrower's answers into the profile, runs the schema and checks.py, and asks up to 3 questions until nothing is missing or inconsistent.
  2. core.routing picks which specialists to run: all three for a new profile, only the affected ones after a what-if. Results from the others carry over.
  3. The specialists run in parallel, each inside guarded().
  4. The Explainer computes the signals and the facts sheet, then writes the report with the LLM, or with the template when the LLM is off or fails.
  5. The Critic runs its rules, then the LLM review. Fixes go back to the Explainer, at most MAX_REVISIONS times.
  6. publish_report checks the escalation rules. A failed review, a red sustainability signal, or every service being down sends the report to counselor_review first.
  7. await_borrower shows the report. A what-if goes through the allow-list, the no-op check and the validators, then back to step 2. "Done", "give up" or the round limit goes to action_plan, then counselor_signoff.

Notes for Peter

  1. Nothing in agents/lender_match.py, risk.py or policy.py changed. agents/_common.py now re-exports core/case.py, so your imports still work.
  2. Property type can now be townhouse_pud or townhouse_condo. The Policy stand-in checks for "townhouse", so it should treat townhouse_condo like a condo.
  3. A failed specialist is now source="unavailable" in the schema. Lender Match can return that instead of stand-in numbers when the service is down (B7).
  4. The signals use historical_applications to leave out lenders with under 200 applications, so please keep filling it from the service.
